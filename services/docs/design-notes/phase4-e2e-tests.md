# Phase 4 E2E Tests

Problem: Phase 4 spreads one logical decision across two runtimes. A saga publishes `fraud.score.requested`, a Python worker enriches over gRPC, scores through LangGraph and an OpenAI-compatible provider, persists an audit session, and publishes a verdict that a Go consumer turns into a review transition. The per-component tests from P1-P8 each prove one hop. None of them prove the properties that only exist across hops: that scoring never delays `payment.execute`, that a malformed or identifier-bearing model response is retried rather than published, that duplicate events collapse to one session and one `tx.paused`, and that no raw user or wallet ID survives the trip into a prompt, an event, a log, or an audit row.

Structure: The suite splits along the runtime boundary rather than trying to span it in one process. `tests/fraud/test_phase4_e2e.py` assembles the real worker, scoring graph, provider registry, guard, validator, and Kafka publisher, and varies only three seams — a deterministic OpenAI-compatible server, the enrichment source, and the audit store. Scripting responses at the HTTP layer keeps provider switching a configuration change and lets tests assert against captured request bodies, which is where the privacy claims are actually checkable. `services/internal/phase4e2e` drives the orchestrator, its Kafka consumer, and the notification service against a fraud worker double that emits the published event contract, so Go-side ordering, idempotency, and race behavior are exercised without a Python process. Both halves run offline through `make test-phase4-e2e`. Cross-runtime concerns that only exist once real infrastructure is present — a single Jaeger trace spanning both services, healthy Prometheus targets, provisioned Grafana panels — move to `devtools/phase4_smoke`, which waits at most 30 seconds per boundary and names the boundary that failed.

Tradeoffs: The event contract is asserted twice, once per runtime, instead of once end-to-end. That is the cost of keeping the default test command fast and dependency-free, and it is bounded because both halves assert against the same published JSON shape; the deployed smoke is what proves they agree in practice. The worker double on the Go side does not score, so verdict *derivation* is only covered in Python, and the Python half does not run a saga, so review transitions are only covered in Go. Writing the trace context into `outbox_events` was required rather than optional: without a carrier on the row, the relay started a fresh trace and the smoke's single-trace assertion could not hold no matter how the test was written.
