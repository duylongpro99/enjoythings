# Phase 1 Spec: Wallets

**Phase:** 1 - Monolith  
**Priority:** P2  
**Status:** Draft  
**Last updated:** 2026-06-02

## Purpose

Implement wallet lifecycle and balance reads for authenticated users. Wallets are the source of current balance state in Phase 1 and enforce the non-negative balance invariant together with transfer logic and database constraints.

## Scope

Wallets include:

- Creating a wallet for the authenticated user.
- Reading wallet details by wallet ID.
- Reading current wallet balance by wallet ID.
- Enforcing wallet ownership for reads.
- Storing balances as integer cents.
- Supporting one currency per wallet, defaulting to `USD`.

Wallets exclude direct deposit, withdrawal, balance mutation outside transfers, multi-currency conversion, account closure, and admin access.

## API

### `POST /v1/wallets`

Creates a wallet owned by the authenticated user.

Request body:

```json
{
  "currency": "USD"
}
```

`currency` is optional. If omitted, use `USD`. Phase 1 should accept only `USD` unless a later spec expands currency support.

Success response: `201 Created`

```json
{
  "id": "6ed87f1f-7c9d-48d6-b23a-4d6255028c5c",
  "user_id": "449b3f19-8b5b-4f4b-b5d0-8e77d97d5c84",
  "balance": 0,
  "currency": "USD",
  "created_at": "2026-06-02T00:00:00Z",
  "updated_at": "2026-06-02T00:00:00Z"
}
```

### `GET /v1/wallets/:id`

Returns wallet details when the wallet belongs to the authenticated user.

Success response: `200 OK`

```json
{
  "id": "6ed87f1f-7c9d-48d6-b23a-4d6255028c5c",
  "user_id": "449b3f19-8b5b-4f4b-b5d0-8e77d97d5c84",
  "balance": 1500,
  "currency": "USD",
  "created_at": "2026-06-02T00:00:00Z",
  "updated_at": "2026-06-02T00:00:00Z"
}
```

### `GET /v1/wallets/:id/balance`

Returns only balance-oriented data.

Success response: `200 OK`

```json
{
  "wallet_id": "6ed87f1f-7c9d-48d6-b23a-4d6255028c5c",
  "balance": 1500,
  "currency": "USD"
}
```

## Domain Rules

- Wallet IDs are UUIDs generated by Postgres.
- `user_id` comes from the authenticated principal, not the request body.
- `balance` is `BIGINT` in the database and `int64` in Go.
- Balance represents cents. Never use floating point for money.
- New wallets start at balance `0`.
- Balance must never be negative.
- Only the owning user may read a wallet in Phase 1.

The domain package should expose a wallet type and invariant methods such as `CanDebit(amount int64) bool` or `Debit(amount int64) error`, but actual persisted mutation is coordinated by the transfer service.

## Database

Wallet schema:

```sql
CREATE TABLE wallets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL,
  balance BIGINT NOT NULL DEFAULT 0,
  currency CHAR(3) NOT NULL DEFAULT 'USD',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT wallets_non_negative_balance CHECK (balance >= 0)
);
```

Indexes:

```sql
CREATE INDEX wallets_user_id_idx ON wallets(user_id);
```

## Layer Responsibilities

Handler:

- Parse wallet ID path params.
- Parse create request body.
- Read authenticated principal from context.
- Map service errors to HTTP responses.

Service:

- Enforce ownership.
- Enforce supported currency.
- Return domain errors for not found, forbidden, and invalid currency.

Repo:

- Use sqlc-generated queries.
- Keep query methods narrow and explicit.
- Do not return database driver errors directly to handlers.

## Error Responses

| Condition | Status | Code |
|---|---:|---|
| Invalid wallet UUID | `400` | `invalid_request` |
| Unsupported currency | `422` | `unsupported_currency` |
| Wallet not found | `404` | `wallet_not_found` |
| Wallet belongs to another user | `404` | `wallet_not_found` |

Returning `404` for another user's wallet avoids leaking wallet existence.

## Testing Requirements

- Handler tests cover request parsing, auth context usage, and response mapping.
- Service tests cover create, read own wallet, reject unsupported currency, not found, and ownership mismatch.
- Repository integration tests cover insert and read paths against Postgres.
- Domain tests cover non-negative balance invariant helpers.

## Acceptance Criteria

- Authenticated user can create a USD wallet with balance `0`.
- Authenticated user can read their wallet details.
- Authenticated user can read their wallet balance.
- User cannot read another user's wallet.
- Invalid UUIDs return `400`.
- Unsupported currency returns `422`.
- Balance is represented as integer cents in API, Go, and database.
